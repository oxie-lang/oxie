# Releasing

Where Oxie and its editor extensions are published, and how each is released.

## Where things are published

| What | Public page | Managed at |
|---|---|---|
| Oxie releases (binaries, installers, notes) | https://github.com/oxie-lang/oxie/releases | tags `vX.Y.Z` in this repository |
| Homebrew formula (`brew install oxie-lang/tap/oxie`) | https://github.com/oxie-lang/homebrew-tap | `Formula/oxie.rb`, written by the release workflow from `dist-workspace.toml` |
| Crates (`cargo install oxie`, `oxie-build` for projects) | https://crates.io/crates/oxie, https://crates.io/crates/oxie-build, https://crates.io/crates/oxie-compiler, https://crates.io/crates/oxie-from-rust | `cargo publish` by hand (step 2 below) |
| Documentation | https://oxie.bkymz.net | Netlify (`netlify.toml`), built from `website/` on every push |
| Claude Code skill (`claude plugin install oxie --marketplace oxie-lang/oxie`) | `skills/oxie` in this repository | `.claude-plugin/marketplace.json`; nothing to publish |
| VS Code extension, VS Code Marketplace | https://marketplace.visualstudio.com/items?itemName=oxie-lang.oxie | https://marketplace.visualstudio.com/manage/publishers/oxie-lang (publisher `oxie-lang`) |
| VS Code extension, Open VSX (VSCodium, Cursor, Windsurf, Gitpod) | https://open-vsx.org/extension/oxie-lang/oxie | https://open-vsx.org/user-settings/namespaces/oxie-lang (namespace `oxie-lang`; ownership claim: https://github.com/EclipseFdn/open-vsx.org/issues/14687) |
| VS Code extension, each `.vsix` | https://github.com/oxie-lang/oxie/releases (tags `vscode-vX.Y.Z`) | the extension release workflow |

The Kuana extension (`editors/kuana-oxie`, regenerated with `editors/build-kuana-extension.sh`)
is not published anywhere yet.

## Oxie

1. Bump `version` in `[workspace.package]` and the versions in `[workspace.dependencies]` of the
   root `Cargo.toml`, and add the version's section to `CHANGELOG.md` (it becomes the GitHub
   release notes).
2. Publish to crates.io (after `cargo login`):
   `cargo publish -p oxie-compiler -p oxie-build -p oxie-from-rust -p oxie`.
3. Tag and push: `git tag -a v0.3.0 -m "Oxie 0.3.0" && git push origin v0.3.0`.
   `.github/workflows/release.yml` (generated by `dist`, configured in `dist-workspace.toml`;
   rerun `dist generate` after changing it) builds macOS, Linux and Windows binaries and creates
   the GitHub release with shell and PowerShell installers. Its `publish-homebrew-formula` job
   then commits `Formula/oxie.rb` to the Homebrew tap (repository secret `HOMEBREW_TAP_TOKEN`: a
   fine-grained token with read and write access to the contents of `oxie-lang/homebrew-tap`).
   When that job fails, the release still exists but the `announce` job is skipped. Edit the
   formula through `dist-workspace.toml`, never in the tap.

## VS Code extension

The extension runs `oxie lsp`, so release Oxie first when the language server changes.

1. Bump `version` in `editors/vscode-oxie/package.json` and commit.
2. Tag and push the same version: `git tag vscode-v0.1.1 && git push origin vscode-v0.1.1`.
3. `.github/workflows/vscode-release.yml` builds `oxie` from the tagged commit, runs the
   extension's tests against it, packages `oxie-0.1.1.vsix`, attaches it to a GitHub release
   (not marked latest, so the installers keep following the compiler's release), and publishes
   it to Open VSX. The run's summary links to every page above.
4. VS Code Marketplace, by hand: download the `.vsix` from the GitHub release, open
   https://marketplace.visualstudio.com/manage/publishers/oxie-lang, choose **Update** in the
   extension's `...` menu, and upload it. Microsoft verifies it within a few minutes.

To check a change without publishing, run the workflow by hand (Actions, "Release VS Code
extension", Run workflow): it runs the tests and keeps the `.vsix` as an artifact.

### Open VSX trusted publishing

Open VSX publishes without a stored token: the workflow is registered as the trusted
publisher of `oxie-lang.oxie` at https://open-vsx.org/user-settings/trusted-publishers
(repository `oxie-lang/oxie`, workflow `vscode-release.yml`), and authenticates with GitHub's
short-lived OIDC token (`ovsx publish --trusted-publishing`). Registering needs the owner role
in the `oxie-lang` namespace, which comes with the approved ownership claim. Until then, or if
the registration is ever lost, upload the `.vsix` at https://open-vsx.org/publish, or add an
`OVSX_PAT` secret (a token from https://open-vsx.org/user-settings/tokens), which the workflow
uses instead.

### Why the Marketplace upload is manual

Automatic Marketplace publishing needs either an Azure DevOps personal access token (global
tokens, the kind it needs, are retired on December 1, 2026) or a managed identity with workload
identity federation, and new Azure DevOps organizations require an Azure subscription. If that
is set up, add the repository secret `VSCE_PAT` (or change the step to
`vsce publish --azure-credential`) and the workflow publishes to the Marketplace too.
